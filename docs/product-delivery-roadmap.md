# FINTRACE 产品审阅与交付路线

> 本文是 2026-10-01 的可执行计划草案，文中新增页面、流程、验收和时间安排均为“未实现/建议”，不改变现有代码或既有 M0–M5 验收事实。工程与核验状态以 [技术路线](roadmap.md) 为准；本文负责产品工作流、演示交付与比赛材料。官方要求有更新时，以[竞赛通知](https://jw.beijing.gov.cn/gjc/tzgg_15688/202608/t20260827_4839055.html)及组委会后续通知为准。

## 1. 目标与当前问题

FINTRACE 定位为“上市公司财报分析与异常线索核查”。用户需要判断：**发生了什么变化、有哪些可能解释、原文支持在哪里、还缺什么、下一步查什么**。产品交付不能只展示核验通过的金额，也不能用一套更漂亮的卡片替代证据与任务闭环。

以下是代码/文档审阅观察，并结合主控查看的 9/30 历史与 10/1 本轮浏览器截图；不把手动回看位置描述成默认打开结果后的页面位置。10/1 自动读取 M2 后聚焦 `annual-report-heading` 的截图显示 scrollY=417、标题 top=16；另有手动按 run_id 回看、查询区展开并 `scrollTo(0,0)` 的截图，属于不同位置。10/1 旁证包括 frontend/tmp/product-audit-20261001/current-home-cli-1366x768.png、current-m2-report-auto-position-1440x900.png、current-m2-report-first-1366x768.png、current-m2-report-first-1440x900.png、current-m2-candidates-1440x900.png、current-m2-evidence-preview-1440x900.png；9/30 历史旁证位于 frontend/tmp/reference-redesign-20260930/。正文记录关键现象，不依赖这些临时图片。只读浏览器 GET 报告与证据预览均返回 200，`non_get_api_requests=[]`；未启动任务、写设置或调用真实模型。本轮未重跑 pytest、前端 typecheck/build，也未启动新服务器。

## 2. 事实与状态契约

状态契约适用于文案、颜色、表格和录屏，具体限制贴近对应数值或结论；避免在页面多个位置重复通用免责声明。

| 显示内容 | 必须满足的规则 |
| --- | --- |
| 数值“独立核验通过” | 仅表示该事实的金额、期间、单位/币种、口径及出处达到对应核验条件；不表示变化原因已证明。 |
| 原因/解释 | 区分年报披露内容、模型生成观点和人工解释；展示出处及来源性质。引用存在不等于因果关系已独立证实。 |
| 缺失/待核验 | 缺失不等于 0。未触发筛查不代表公司健康、无风险或整份年报无异常。 |
| 比较结果 | 两边事实分别绑定来源身份并独立核验；公司、期间、单位倍率、币种、报表口径和可比性依据成立后才显示增幅。当前年度路径只承诺已实现的年度比较边界；跨文件季度比较需另建比较依据与核验支持，不能因跨文件一概禁止，也不能默认可比。不可比、基数为零或负数时不显示同比。百分点与百分比明确区分。 |
| M3 分数 | 试行规则分数不是风险概率、置信度或舞弊判断；总分缺失不能按 0 展示。 |
| 模型评审 | AI 评审是观点；被引 ID 绑定或模型自评不能替代独立核验。确定性、M3、AI 调查+最终评审的调用语义必须清楚可见。 |
| 期间/报告状态 | 标注公司、期间、报告类型、来源、任务状态和回放/新运行。历史归档不称为实时分析。 |

## 3. 页面结构建议

### 入口与任务列表

- 主页唯一主操作为“分析年报”；提供“使用已有材料”和“上传文本型 PDF”两个等价起点，输入公司代码、报告期间/类型后再选分析模式。
- 模式说明紧邻选择项：确定性年度核验；标准分析 + M3 四规则试行；AI 调查与最终评审。显示各模式实际调用、数据外发、等待和依赖；不可组合时明确写明边界。
- 成功任务列表需要后端索引，显示公司、期间、来源、完成/中断状态、模式、创建时间和 run_id。job_id 恢复一个在途任务不等于历史列表。
- 设置继续独立存在；旧“基础预检”保留 API 和页面兼容，主导航归入旧流程区，不与正式年度分析混称。

### 结果页

1. **页头**：公司、报告期、报告类型、回放/新运行、任务状态、来源文件与归档编号。
2. **主要发现**：一个重点变化；变化方向/金额；数值核验状态；解释状态（已披露/模型观点/尚无证据）；一条原文证据入口。异常线索只作为待核查事项。
3. **指标对照**：本期、上期、差额/同比、期间、币种/单位、合并或母公司口径、可比性状态、来源状态。不能计算的单元格直接写原因，不留空白误导。
4. **业务问题线索**：变化事实、需要解释的问题、建议查看的材料；事实、推论、模型观点分别标记。空 reason 不补写成原因。
5. **证据与方法**：已核实来源、待定位项和待核验项；公式/输入、校验规则、调用审计置于可展开的审计详情，但关键限制不折叠。

### 证据与方法

当前 UI 已能读取已核验页图、黄色数值区域高亮，且对无可靠页码的证据标“原文位置待定位”。本轮 10/1 证据预览截图中，高亮区域已存在；整页预览把金额区域推到视口下方，主张和数值上下文容易滚走。计划复用现有证据 ID、value_region 和高亮页图，在证据侧栏/抽屉按“页码—表名—行—列—原值—标准值—单位—币种—期间—口径”展示有值字段，并让页图默认聚焦/缩放到金额区域；不重做页图或高亮能力。内部 fact/calculation/claim ID、哈希和完整调用审计保留在审计详情。

## 4. 视觉与交互验收建议

- 以财务工作台为方向：数字右对齐、tabular-nums、表头和单位清楚；减少连续大卡片，采用行分组、轻分隔和少量状态标记。
- 一个主色；颜色之外同时使用文字/图标编码状态。禁止仅靠红绿表达涨跌或风险。
- 正文 14–16px；录屏关键字至少 16px。表格长字段允许换行或横向滚动，页面本身不横向溢出。
- 目标是高密度但可读的财务工作台；通过删重、分组和对齐提高信息效率，不靠单纯缩小字号把更多文字塞进首屏。
- 1366×768 与 1440×900、100% 缩放首屏须出现公司/期间、任务/数据状态、主要发现和关键金额或缺口；不先占屏展示大插画。若第四项指标缺乏可靠单位、币种、口径或出处，明确标缺失，不推造数值；两年数据做对照，不做伪趋势图。
- 390px 宽度下可读、无页面横向溢出；键盘可操作主要流程、焦点清晰；错误、长公司名、长来源名和空状态有验收样例。
- 从主要发现打开原文不超过 2 次点击；方法和限制可展开，但核心状态、金额口径与缺口不可只藏在折叠区。
- 后续由未参与开发的试用者执行理解验收：浏览 30 秒内能说出公司与期间、最重要变化、原因是否已确认、去哪里看证据。此为待执行目标，本轮未做该用户测试。

现有模块优先复用。初赛前不排全面框架重构、登录、OCR、向量库、云部署或花哨动效；先保障主流程与真实案例，最小自动回归可并行，但不能阻塞可录系统冻结和计划书定稿。本轮不实施 CI。

## 7. 交付阶段与关卡

### A：可录原型（产品验收目标）

- 一家公司真实年报完成确定性提取/核验、AI 调查和新增最终评审的端到端任务，产生可回看的新 run、真实来源页和审计记录。
- 可录原型应支持展示：一个明确变化；一条带来源性质标记、由具体原文支持的披露解释或模型解释；一个可点击证据；另有一个缺证时不越界下结论的示例。引用不等于因果关系已独立证实。页面操作范围与取材顺序见[视频负责人交接说明](../submission/video/video-handoff.md)。
- 如果材料只找到标题或目录，应做年报内定向检索；仍没有支持材料时，原型应明示“原因分析验收未完成”，不能把只展示弃权当作原因分析已完成。
- 四规则 M3 与 AI 当前互斥，集成是单列工作。若截止前未组合，系统分别显示两个模式的边界和适用范围，不得用 UI 伪装成同一任务已完成；取材时按[视频负责人交接说明](../submission/video/video-handoff.md)交代。
- A 的边界是一个可复核原型，不声称跨公司泛化。当前模型能力此前一次本机查询为 ready，但状态会变；真实在线最终评审仍需完整验收，本路线不调用真实供应方。

### B：初赛计划书与系统交接

- 初赛计划书 PDF 的完善属于本轮初赛材料工作；`submission/proposal/` 保存可编辑源稿，由计划书负责人继续核对并定稿。
- 产品/技术组向视频负责人交付可录系统版本的提交号或关键文件哈希、经核对的真实 run_id、原文证据入口、页面操作顺序、复现材料及软件限制。建议页面顺序是：选已有材料或上传文本型 PDF，确认公司/年度/模式，启动任务并查看阶段和来源，打开报告与候选，再进入已核验的原文页图，最后回看运行与版本信息。
- 可作选材起点的真实归档包括 M2 `annual-analysis-ffcd6078-a1df-416b-88b8-6774ebe66d42` 和 M3 `annual-analysis-5e7079fe-9ac9-4e96-85fa-1898f9177d21`；二者都是确定性运行。历史在线模型调查 `annual-analysis-a32c16a7-00da-48c5-a97d-59ee284904df` 不含后来增加的最终评审，不能称为当前完整 AI 流程的在线验收。视频取材、回放/新运行标注及素材要求见[视频负责人交接说明](../submission/video/video-handoff.md)。
- 交接时同时说明软件边界：只处理可提取文字的文本型 PDF，不做 OCR；M3 是试行规则且与 AI 模式不能在同一运行组合；页面没有产品级报告导出；缺少可比或出处证据时系统会弃权。
- 视频负责人独立统筹视频脚本、录制、剪辑、编码和 MP4 成片；平台上传由团队指定的提交负责人处理。产品路线只定义可演示系统的状态与交接输入，不代管视频制作或上传排期。
- 海天、茅台和五粮液的本机原始 PDF 尚未确认再分发许可，原始 PDF 与整页图像不作为可公开交付素材；如需复现，可提供官方获取指引、SHA256 和准备步骤，或改用许可明确的数据。

### C：决赛成品（内部目标）

- 最终报告书、可运行原型、完整源代码、依赖和运行说明、评审现场可实时处理的样例数据；现场演示与提交代码/提示词/依赖版本一致。C-03 负责非原开发机复现关卡。
- 组织人工核对案例：会计变更、非经常性损益、利润与现金流背离；以及 C-02 定义的一条同时覆盖季度同比和环比的完整案例。三至五家公司及季度案例均为内部目标，不是官方最低数量。
- 多公司样例保留未用于适配的案例、清洁对照及明确标记的异常/构造错误；提供来源与使用条件。云 API 与网络条件按现场规则核实。重新运行受模型供应方影响，不承诺逐字一致，应保证输入、模型标识、调用审计和结果差异可查。
- 竞赛通知要求评审现场可实时处理样例并提交完整代码和运行说明；CI、登录、OCR 和云部署不是通知硬性要求。

## 9. 本轮边界

初赛计划书的完善仍属于本轮初赛材料工作；本产品路线保留其与可录系统的交接节点。视频脚本、录制、剪辑、编码和 MP4 成片由视频负责人按[独立交接说明](../submission/video/video-handoff.md)承接；平台上传由团队指定的提交负责人处理。本路线给出可录系统所需的版本、真实运行、原文证据、页面动作、软件限制和交接信息，不代替视频负责人制定制作排期。本文没有重跑 pytest、前端 typecheck/build、启动新服务器或调用真实模型；README/AGENTS 中记录的检查结果是历史事实，不是本轮重跑结果。本路线中的产品建议尚未实现；现有 M0–M5 的事实、状态和范围仍见 [技术路线](roadmap.md)。
