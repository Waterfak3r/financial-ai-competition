# FINTRACE 路线

时间按关卡排列，不承诺日期。首版不做 OCR、向量库、GraphRAG、模型训练、用户系统和云部署。计划书与视频独立，不在这些关卡里。保留现有模块，旧年度预检与新的 v2 年度分析流程分开；本地单进程同时只跑一个活动任务，重启后把未完成任务标成中断失败。正式报告保留缺口，原文、计算和引用要能回溯。

状态分为“已编码”“已集成”“已验收”。通过测试串联不等于已有正式产品入口；目标流程是提取、事实核验、确定性计算与筛查、解释与调查、主张核验、报告。补充检索最多一次。

核验必须重读 PDF，不能复用提取阶段已经做出的最终行列判断。事实核验状态为 `verified`、`conflict`、`insufficient_evidence`。追溯状态未知时不默认可比。零或负基数只保留差额，增速弃权。非经常性损益披露合计不直接除以归母净利润。主张分为 `fact`、`calculation`、`inference`、`hypothesis`。同比是 `calculation`。模型自评不能代替独立核验。未验证内容进入待核查区。

## 下一步顺序

1. 保持可比性检查失败关闭，并增加经审阅的多公司、多年度验证；不可把一个样例的报告内 proof 扩大解释为普遍成立或等同于跨年报勾稽。
2. 接入 LangGraph，完成模型解释、只针对已生成候选信号的年报内检索和经审计的调用流程。补充检索最多一次；先通过本地模拟接口，再等用户配置供应方与密钥后进行在线验收。当前没有真实在线模型运行。
3. 建设 Evidence Explorer、多公司人工 golden 与有/无独立核验的对照评测，覆盖错金额、错单位、错年度列、错口径和无支持主张；报告误报、漏报、弃权、覆盖率和耗时。
4. 再评估 v2 API、前端报告展示、任务进度与产品级导出。

## 测试与评测

M1 起注入错金额、错单位、错年度列、错口径和无证据主张。集成与回归应覆盖真实提取输出，而非只使用手工构造的理想对象。M4 对相同候选比较有核验与无核验，报告错误检出、误拦截、漏检、弃权、覆盖和耗时。人工答案与事后处罚信息只作为评测标签，与分析材料隔离。
