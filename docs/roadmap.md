# FINTRACE 技术里程碑

本文维护工程能力与完成条件；[产品交付路线](product-delivery-roadmap.md)负责从可录原型、初赛材料到决赛成品的任务顺序。两者是不同视角，不是两套并行开发指令；具体工作以用户当前任务为准。年度可用性恢复的阶段状态及通过条件见[恢复任务书](annual-analysis-recovery-plan.md)，代码基线、各阶段提交和运行证据集中在[验收记录](verification-history.md)。活动执行/预算合同见[架构](architecture.md#annual-execution-budget)。历史验收不代表当前工作区已经验证。

独立 M3 筛查与 AI 分析是分开的层。两个显式 AI 年度模式均执行全文发现、固定候选调查和最终评审；全文发现独立于候选、已确认指标及 M3。当前事项层保留全部合格发现的成员处理路径与同源补证，再构造新评审完整输入；尺寸或预算不足时明确待处理。旧 review_v2 保留最多十二条优先发现的原有输入语义，不将其改标为新全局评审。新版归并、恢复与在线关卡的通过范围以恢复任务书为准。`integrated_analysis` 可在同一 job/run/report 额外执行独立 M3 层。M3 审计不改变事实核验或模型观点状态；海天四规则总分为零只表示该次有限规则未触发，不表示公司无风险。全文处理上限与覆盖语义见[全文发现契约](annual-discovery.md)，活动时限见[架构](architecture.md#annual-execution-budget)。

## 与产品交付的衔接

按 [产品路线任务表](product-delivery-roadmap.md#6-可执行任务)逐项实施和验收：先解决可录原型的有效信息、主要发现与证据查看，以及实际 AI 流程的验收缺口；再推进多公司评测、交付包装和目标扩展。路线中的排期是建议，不是比赛通知，也不授权一次性重构。

工程验收应同时回答：是否已有代码、是否接入实际入口、是否完成指定样例/范围的验证。CLI 通过不替代 Web 验收，mock 通过不替代在线调用，历史回放不替代新运行，多份 PDF 不等于多公司完整分析。

## 保持的核心契约

- 核验重新读取 PDF，不直接复用提取器的最终行列判断；事实、计算、模型观点分开。
- 未知币种、单位、期间、口径或可比性时弃权；仅当两个输入都独立核验通过且可比性成立才保留差额；此时非正比较基数仍不计算增长率。任一输入未核验或比较证据不足时，差额和增长率均弃权；缺失不当作零。
- 当前进程签发的 proof 只在该进程授权；序列化副本只作审计。普通 VerificationResult 对象不是签名凭据。
- 固定候选调查限于同源年报并保留补充检索约束；全文发现扫描目标覆盖可提取文字，但受批次/字符/时间预算限制，失败和遗漏需明确报告。最终评审仍是观点，引用绑定不证明语义正确。
- 旧预检与 v2 分开且兼容历史读取，不补写历史上未执行的核验。
- 多公司 provisional 案例不能冒充人工 golden；受控错误测试不能替代真实异常识别评测。
