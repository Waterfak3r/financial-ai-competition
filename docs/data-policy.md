# 数据、证据与产物管理

## 1. 当前数据状态

当前项目资料包含用户提供的比赛通知及方案大纲，没有导入财报、样例数据、人工标注或业务运行结果。以下内容是后续数据进入项目时的管理约定。

## 2. 分类存放

| 内容 | 位置 | 默认版本管理策略 |
| --- | --- | --- |
| 原始财报及附注 | data/raw/ | 忽略内容，保留目录占位 |
| 解析文本、表格、事实与索引 | data/processed/ | 忽略内容，保留目录占位 |
| 可交付演示样例 | data/samples/ | 可纳入，先记录来源与使用条件 |
| 案例说明、人工标注和评测标签 | evaluation/cases/ | 可纳入，保持与原始输入区分 |
| 执行记录和必要中间结果 | artifacts/runs/<run_id>/ | 本地归档，默认忽略 |
| 自动生成的报告 | artifacts/reports/<run_id>/ | 本地归档，默认忽略 |
| 评测结果 | artifacts/evaluations/<evaluation_id>/ | 本地归档，默认忽略 |
| 模块内临时内容 | 对应目录的 tmp/<task_id>/ | 忽略 |
| 跨模块临时内容 | artifacts/tmp/<task_id>/ | 忽略 |
| 比赛材料与其源文件 | submission/ 对应阶段目录 | 可纳入，依据材料大小和发布需要管理 |

默认忽略不代表可以删除；正式运行证据和临时文件有不同的保留要求。

## 3. 来源与原始文件

- 仅使用公开、获授权或明确允许用于项目的材料，来源和使用条件随数据记录。
- 导入时为文档分配标识，记录原文件名、公司标识、报告类型与期间、发布日期、下载地址或本地来源、获取时间和文件哈希。
- 建议按公司和报告期组织原始资料，如 data/raw/<company_id>/<report_period>/<document_id>/，保留原始文件。
- 原始资料保持原样，解析、清洗和修正不得覆盖原文件。
- 同名但不同内容的文件按文档标识分开保存，并记录各自来源。
- 处理后结果引用对应 document_id 和原始文件哈希；需要纠正提取值时记录修正原因及依据。
- 第三方模型、代码和数据投入使用时补充版本、来源、许可证或使用条件、具体用途；不得把第三方成果描述为自主成果。

上述名称用于表达目录约定，尚未实现自动导入或元数据格式。

## 4. 财务事实与证据

结构化事实需要同时保留：

- 文档标识、原始文件哈希、PDF 页序号以及原文页码（如存在）。
- 所属表格、行列位置或原文片段；具备定位条件时保留坐标。
- 公司、指标名称、原始文字和规范化数值。
- 报告期、时点或期间类型，年度、季度或累计口径。
- 币种、单位倍率，合并报表或母公司报表口径。
- 本期数、比较期数及是否追溯调整等上下文。
- 提取方式、处理过程以及人工修正记录（如有）。

财务计算先核对单位、期间和报表口径。缺失值不得直接当成零，口径冲突不得静默拼接。发现提取错误时回查原文，在处理后数据中修正并保留记录。

结论需绑定事实、计算和引用依据，区分客观数据、分析推论、观点与待核查事项。异常信号用于提示进一步核查，不等同于确认舞弊。

## 5. 运行归档与配置

- 每次运行使用唯一 run_id；报告与执行记录使用相同运行标识建立关联。
- 归档输入文档引用与哈希、代码版本或快照标识、提示词与规则版本、模型标识及参数、工具调用、计算过程、核验结果、错误和输出。
- 若尚无 Git 版本，使用可核对的代码快照或文件哈希记录版本，不虚构提交号。
- 记录文件访问以及实际模型请求、响应、调用时间、模型版本或供应方返回标识、用量和关键结构化结果；记录前移除密钥、鉴权头等敏感凭据。不能只记录提示词模板或随机种子来声称在线模型结果完全可复现。
- .env.example 不包含真实凭据；实际密钥通过环境变量或本地 .env 配置。
- 第一版使用云端 API：原始材料、索引、统计计算与运行记录留在本地；后端只发送公开或获准外发的必要片段，并记录对应文档和页码。第一版不将整库、评测标签或事后处罚材料上传给模型，也不开放任意互联网检索；模型端点和资料白名单独立管理。现场联网范围按比赛环境要求落实。
- 复现说明应交代重新计算与历史输出回放的区别，不能把读取已有报告描述为实时分析。

## 6. 样例与评测

- data/samples/ 用于演示输入；案例清单、人工期望和标签进入 evaluation/cases/。
- 对真实数据、脱敏数据和人工构造数据分别标明性质及处理方法。
- 历史案例分析只使用截止分析时点已公开的材料，记录材料可用时间。
- 后续处罚信息、事后调查结论及人工答案只用于评测，不能进入该案例的历史分析检索范围。
- 对照方案使用相同输入和评测口径；记录样本范围，避免用少量演示案例声称已验证泛化能力。
- 未发现处罚或公开舞弊记录的公司不能直接标记为“已确认无舞弊”，需明确对照样本的标注依据。
- 样本单位为“公司 + 报告期”；标签另附报告类型、受影响文件、处罚所认定的财务事项、受影响期间及标签截止日。只有明确涉及财务虚假记载等事项并能映射到相关财报的认定才作为相应正例依据；一般违规处罚不直接当作财报舞弊标签。
- 区分分析材料截止时间与评测标签观察截止时间。例如后续处罚认定早期财报存在问题，标签对应受影响的早期财报，处罚文本只进入隔离的评测标签区。
- 开发、验证和测试以公司隔离，并设置报告披露时间边界；同一公司的相邻报告期、同一财报的修订版本及衍生片段不得跨集合泄漏。训练集内才能拟合预处理、采样或平衡处理，验证集用于规则与阈值选择，测试集锁定后不参与调参。
- 测试集尽量保留目标使用场景的类别比例；若另建正例富集的压力案例集，应分开报告。未确认对照与未知样本的处理、弃权比例和数据覆盖率必须随指标披露。

## 7. 临时文件与清理

临时文件统一放入 tmp/<task_id>/，就近归属于相关模块；公共临时位置为 artifacts/tmp/<task_id>/。正式样例、报告和复现证据不依赖这些目录。

临时内容转为长期资产前，应整理命名、来源、文档和相关检查，再迁入对应正式目录。已有 tmp/、任务子目录及其中临时文件默认保留，任务结束不主动清理。

仅在用户明确要求清理时，先核对归属和绝对路径范围，再清理获准且确认不再需要的内容；不删除未知任务内容、用户资料或必要证据。自动化清理机制尚未实现，执行清理时由协作者按 AGENTS.md 完成核对。
