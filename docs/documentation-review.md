# 项目 Markdown 审阅与整理记录

审阅日期：2026-10-01。范围为根目录规则、README、docs、evaluation 说明、submission 交接与审阅说明、tem 中的历史材料，以及 config/prompts 的运行时用途。没有把自动生成的报告或第三方依赖文档当作新的项目规则。

结论：Markdown 确实可能影响模型工作，但影响有三种来源。AGENTS 是明确的协作规则；普通文档在被读取后提供上下文，过时内容会误导判断；config/prompts 中的两份文件由后端读取后作为模型系统提示，直接影响产品行为。没有证据证明所有 Markdown 都会自动加载，也不能仅凭文档断言前端问题完全由提示词造成。

## 运行时提示词的实际影响

`backend/src/finagent/agents/annual_investigation.py` 和 `annual_review.py` 分别读取 config/prompts 下的调查与评审文件；它们会进入模型调用，不是给开发人员看的普通说明。

最终评审提示词禁止输出数字、金额、比例与年份；annual_review.py 的解析器还使用数字检查拒绝此类输出。这能限制模型编造数值，却也使 AI 评审本身不能承担包含具体同比的摘要。它是用户所感受到“描述抽象”的一个相关约束，但不能证明是全部原因，也不影响确定性数据在页面上单独展示。

后续产品任务应从已核验的结构化事实/计算生成数值摘要，并将模型解释以观点身份关联展示。若要让模型自由文本包含数值，需另行设计绑定、核验、解析与回归验证。本次仅记录该设计问题，未修改提示词或程序。
