## 1. 目标与当前问题

FINTRACE 定位为“上市公司财报分析与异常线索核查”。用户需要判断：**发生了什么变化、有哪些可能解释、原文支持在哪里、还缺什么、下一步查什么**。产品交付不能只展示核验通过的金额，也不能用一套更漂亮的卡片替代证据与任务闭环。

以下观察是 2026-10-01 代码/文档审阅基线，结合主控查看的 9/30 历史与 10/1 浏览器截图；它们描述当日页面，不代表本次更新后的现状，也不把手动回看位置描述成默认打开结果后的页面位置。10/1 自动读取 M2 后聚焦 `annual-report-heading` 的截图显示 scrollY=417、标题 top=16；另有手动按 run_id 回看、查询区展开并 `scrollTo(0,0)` 的截图，属于不同位置。10/1 旁证包括 frontend/tmp/product-audit-20261001/current-home-cli-1366x768.png、current-m2-report-auto-position-1440x900.png、current-m2-report-first-1366x768.png、current-m2-report-first-1440x900.png、current-m2-candidates-1440x900.png、current-m2-evidence-preview-1440x900.png；9/30 历史旁证位于 frontend/tmp/reference-redesign-20260930/。正文记录当日关键现象，不依赖这些临时图片。审阅当时只读浏览器 GET 报告与证据预览均返回 200，`non_get_api_requests=[]`；未启动任务、写设置或调用真实模型。此段是历史观察，不作为本轮验证记录。

## 2. 事实与状态契约

状态契约适用于文案、颜色、表格和录屏，具体限制贴近对应数值或结论；避免在页面多个位置重复通用免责声明。

| 显示内容 | 必须满足的规则 |
| --- | --- |
| 数值“独立核验通过” | 仅表示该事实的金额、期间、单位/币种、口径及出处达到对应核验条件；不表示变化原因已证明。 |
| 原因/解释 | 区分年报披露内容、模型生成观点和人工解释；展示出处及来源性质。引用存在不等于因果关系已独立证实。 |
| 缺失/待核验 | 缺失不等于 0。未触发筛查不代表公司健康、无风险或整份年报无异常。 |
| 比较结果 | 两边事实分别绑定来源身份并独立核验；公司、期间、单位倍率、币种、报表口径和可比性依据成立后才显示增幅。C-02 已在独立季度 CLI 中实现跨文件比较 proof；仍不能因跨文件一概禁止，也不能默认可比。不可比或输入未核验时差额与增长率均弃权；比较基数为零或负数时保留有依据的差额、弃权增长率。百分点与百分比明确区分。 |
| M3 分数 | 试行规则分数不是风险概率、置信度或舞弊判断；总分缺失不能按 0 展示。 |
| 模型评审 | AI 评审是观点；被引 ID 绑定或模型自评不能替代独立核验。确定性、独立 M3、AI 调查+最终评审及 M3+AI 集成的调用语义必须清楚可见。 |
| 全文发现 | 显式 AI 模式以本 PDF 全部可提取文字为扫描目标，受批次、字符和时间预算限制；coverage 需区分成功、失败、未尝试、截断和无文字页。观点标未核验；priority 仅表示核查顺序。固定比较项可以与动态发现重合，也可能没有动态发现，不能强造差异。 |
| 期间/报告状态 | 标注公司、期间、报告类型、来源、任务状态和回放/新运行。历史归档不称为实时分析。 |

## 3. 页面结构建议

### 入口与任务列表

- 主页唯一主操作为“分析年报”；提供“使用已有材料”和“上传文本型 PDF”两个等价起点，输入公司代码、报告期间/类型后再选分析模式。
- 模式说明紧邻选择项：标准分析、标准分析 + M3 四规则试行、AI 调查与最终评审，以及四规则 + AI 同任务集成。显示各模式实际调用、数据外发、等待和依赖；仅集成模式组合 M3 与 AI，并说明两层各自的处理边界。
- 成功任务列表需要后端索引，显示公司、期间、来源、完成/中断状态、模式、创建时间和 run_id。job_id 恢复一个在途任务不等于历史列表。
- 设置继续独立存在；旧“基础预检”保留 API 和页面兼容，主导航归入旧流程区，不与正式年度分析混称。

### 结果页

1. **页头**：公司、报告期、报告类型、回放/新运行、任务状态、来源文件与归档编号。
2. **主要发现**：一个重点变化；变化方向/金额；数值核验状态；解释状态（已披露/模型观点/尚无证据）；一条原文证据入口。异常线索只作为待核查事项。
3. **指标对照**：本期、上期、差额/同比、期间、币种/单位、合并或母公司口径、可比性状态、来源状态。不能计算的单元格直接写原因，不留空白误导。
4. **业务问题线索**：变化事实、需要解释的问题、建议查看的材料；事实、推论、模型观点分别标记。空 reason 不补写成原因。
5. **证据与方法**：已核实来源、待定位项和待核验项；公式/输入、校验规则、调用审计置于可展开的审计详情，但关键限制不折叠。

### 证据与方法

当前 UI 已能读取已核验页图、黄色数值区域高亮，且对无可靠页码的证据标“原文位置待定位”。本轮 10/1 证据预览截图中，高亮区域已存在；整页预览把金额区域推到视口下方，主张和数值上下文容易滚走。计划复用现有证据 ID、value_region 和高亮页图，在证据侧栏/抽屉按“页码—表名—行—列—原值—标准值—单位—币种—期间—口径”展示有值字段，并让页图默认聚焦/缩放到金额区域；不重做页图或高亮能力。内部 fact/calculation/claim ID、哈希和完整调用审计保留在审计详情。

## 4. 视觉与交互验收建议

- 以财务工作台为方向：数字右对齐、tabular-nums、表头和单位清楚；减少连续大卡片，采用行分组、轻分隔和少量状态标记。
- 一个主色；颜色之外同时使用文字/图标编码状态。禁止仅靠红绿表达涨跌或风险。
- 正文 14–16px；录屏关键字至少 16px。表格长字段允许换行或横向滚动，页面本身不横向溢出。
- 目标是高密度但可读的财务工作台；通过删重、分组和对齐提高信息效率，不靠单纯缩小字号把更多文字塞进首屏。
- 1366×768 与 1440×900、100% 缩放首屏须出现公司/期间、任务/数据状态、主要发现和关键金额或缺口；不先占屏展示大插画。若第四项指标缺乏可靠单位、币种、口径或出处，明确标缺失，不推造数值；两年数据做对照，不做伪趋势图。
- 390px 宽度下可读、无页面横向溢出；键盘可操作主要流程、焦点清晰；错误、长公司名、长来源名和空状态有验收样例。
- 从主要发现打开原文不超过 2 次点击；方法和限制可展开，但核心状态、金额口径与缺口不可只藏在折叠区。
- 后续由未参与开发的试用者执行理解验收：浏览 30 秒内能说出公司与期间、最重要变化、原因是否已确认、去哪里看证据。此为待执行目标，本轮未做该用户测试。

初赛计划书的完善属于独立材料工作；本路线只保留其与可录系统的交接节点。视频脚本、录制、剪辑、编码和 MP4 成片由视频负责人按[独立交接说明](../submission/video/video-handoff.md)承接；平台上传由团队指定的提交负责人处理。本路线提供可录系统所需的版本、真实运行、原文证据、页面动作、软件限制和交接信息，不代替视频负责人制定制作排期。本轮具体检查及证据位置见[验收记录](verification-history.md)；本文件不复制测试流水。当前产品状态按本文第 6–7 节读取，工程里程碑的范围与限制仍见[技术路线](roadmap.md)。
