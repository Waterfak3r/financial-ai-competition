# FINTRACE 路线

时间按关卡排列，不承诺日期。首版不做 OCR、向量库、GraphRAG、模型训练、用户系统和云部署。计划书与视频独立，不在这些关卡里。保留现有模块，旧年度预检与新的 v2 年度分析流程分开；本地单进程同时只跑一个活动任务，重启后把未完成任务标成中断失败。正式报告保留缺口，原文、计算和引用要能回溯。

状态分为“已编码”“已集成”“已验收”。通过测试串联不等于已有正式产品入口；目标流程是提取、事实核验、确定性计算与筛查、解释与调查、主张核验、报告。补充检索最多一次。

核验必须重读 PDF，不能复用提取阶段已经做出的最终行列判断。事实核验状态为 `verified`、`conflict`、`insufficient_evidence`。追溯状态未知时不默认可比。零或负基数只保留差额，增速弃权。非经常性损益披露合计不直接除以归母净利润。主张分为 `fact`、`calculation`、`inference`、`hypothesis`。同比是 `calculation`。模型自评不能代替独立核验。未验证内容进入待核查区。

当前有海天、茅台、五粮液三份 2024 年真实年报用于跨公司事实核验代码检查，但这不等于三家公司均完成年度分析验收或形成 M4 人工 golden。茅台样例的 8 条事实已独立确认为 `verified`，可比性证据不足，8 项计算均未确认。五粮液样例定位到 8 条数值，但年报对应表未披露币种，当前代码与集成测试将 8 条事实及计算留在未确认状态。两个评测案例均为 `agent_provisional_pending_human`，不是人工 golden。五粮液 `0.00` 的 Decimal 误判已在代码中修正，但修正后的正式 run 与案例尚待重新归档；旧归档中的可比性 `conflict` 是此前结果，不作为当前结论。

## 下一步顺序

1. 保持可比性检查失败关闭；人工审阅茅台与五粮液 provisional 案例，并在修正五粮液 `0.00` Decimal 误判后重新归档正式运行和案例。继续扩展多公司、多年度验证；不把单份报告内 proof 解释为普遍结论或等同于跨年报勾稽。
2. 在可用环境启用 `agents` 可选依赖并完成 LangGraph mock 集成验收。调查图只对已生成候选信号使用同源年报检索，补充检索最多一次。当前没有真实在线模型运行；供应方、型号和密钥由用户配置后再做在线验收。
3. 完成 3 到 5 家公司的人工 golden、有/无独立核验消融与可靠性统计，覆盖错金额、错单位、错年度列、错口径和无支持主张；报告误报、漏报、弃权、覆盖率和耗时。当前两份跨公司案例仍待人工审阅。
4. 评估 v2 分析创建/启动 API、任务进度与产品级导出。当前只读报告 API、Evidence Explorer 和独立证据预览已集成；页面不启动分析、不提供产品级导出。

## 测试与评测

M1 起注入错金额、错单位、错年度列、错口径和无证据主张。集成与回归应覆盖真实提取输出，而非只使用手工构造的理想对象。M4 对相同候选比较有核验与无核验，报告错误检出、误拦截、漏检、弃权、覆盖和耗时。人工答案与事后处罚信息只作为评测标签，与分析材料隔离。

截至 2026-09-27，最近完整后端检查为 241 passed、1 skipped；跳过项是因当前环境未安装可选 LangGraph 依赖而跳过的 mock 调查集成测试。前端 `npm run build` 通过；海天归档报告与 PDF 第 82 页独立证据预览已完成浏览器 smoke。上述检查与浏览器验收不等于 M3 在线模型验收或 M4 人工 golden/消融完成。
