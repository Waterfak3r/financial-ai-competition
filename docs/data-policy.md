## 2. 分类存放


| 内容 | 位置 | 默认版本管理策略 |
| --- | --- | --- |
| 原始财报及附注 | data/raw/ | 忽略内容，保留目录占位 |
| 解析文本、表格、事实与索引 | data/processed/ | 忽略内容，保留目录占位 |
| 可交付演示样例 | data/samples/ | 可纳入，先记录来源与使用条件 |
| 案例说明、人工标注和评测标签 | evaluation/cases/ | 可纳入，保持与原始输入区分 |
| 执行记录和必要中间结果 | artifacts/runs/<run_id>/ | 本地归档，默认忽略 |
| 自动生成的报告 | artifacts/reports/<run_id>/ | 本地归档，默认忽略 |
| 异步年度分析任务状态 | artifacts/annual-analysis-jobs/<job_id>/ | 本地持久化，默认忽略 |
| 评测结果 | artifacts/evaluations/<evaluation_id>/ | 本地归档，默认忽略 |
| 模块内临时内容 | 对应目录的 tmp/<task_id>/ | 忽略 |
| 跨模块临时内容 | artifacts/tmp/<task_id>/ | 忽略 |
| 比赛材料与其源文件 | submission/ 对应阶段目录 | 可纳入，依据材料大小和发布需要管理 |

默认忽略不代表可以删除；正式运行证据和临时文件有不同的保留要求。

## 3. 来源与原始文件


- 仅使用公开、获授权或明确允许用于项目的材料，来源和使用条件随数据记录。
- 导入时为文档分配标识，记录原文件名、公司标识、报告类型与期间、发布日期、下载地址或本地来源、获取时间和文件哈希。
- 建议按公司和报告期组织原始资料，如 data/raw/<company_id>/<report_period>/<document_id>/，保留原始文件。
- 原始资料保持原样，解析、清洗和修正不得覆盖原文件。
- 同名但不同内容的文件按文档标识分开保存，并记录各自来源。
- 处理后结果引用对应 document_id 和原始文件哈希；需要纠正提取值时记录修正原因及依据。
- 第三方模型、代码和数据投入使用时补充版本、来源、许可证或使用条件、具体用途；不得把第三方成果描述为自主成果。


上传公司/年度来自请求，不等于已独立核实 PDF 内容；分析启动仍需校验来源目录、source.json 身份与哈希。解析、纠错和标准化另写 data/processed；上传不覆盖既有资料。上传、任务及失败回滚约定见架构文档。

## 4. 财务事实与证据


结构化事实需要同时保留：

- 文档标识、原始文件哈希、PDF 页序号以及原文页码（如存在）。
- 所属表格、行列位置或原文片段；具备定位条件时保留坐标。
- 公司、指标名称、原始文字和规范化数值。
- 报告期、时点或期间类型，年度、季度或累计口径。
- 币种、单位倍率，合并报表或母公司报表口径。
- 本期数、比较期数及是否追溯调整等上下文。
- 提取方式、处理过程以及人工修正记录（如有）。

财务计算先核对单位、期间和报表口径。缺失值不得直接当成零，口径冲突不得静默拼接。发现提取错误时回查原文，在处理后数据中修正并保留记录。

年度分析页面显示 PDF 物理页序号，并保留位置来源的状态：同源且通过独立核验的证据可进入白名单页图预览；仅由未核实提取结果定位的页码标为“待核实定位”，不提供独立核验证据页图入口。来源绑定、页码区域或相关事实不足以支持可靠定位时显示“原文位置待定位”，不根据印刷页码或相邻页面推测。


结论绑定事实、计算和出处；fact、calculation、inference、hypothesis 分开。异常信号不等于舞弊，模型自评或引用 ID 校验不能替代独立核验。独立核验重读原 PDF，不直接相信提取器的最终判断。

未知追溯状态不默认可比；非正比较基数不计算增速；非经常性损益披露合计不直接当作扣非归母净利润。当前年度 proof 只在签发进程内生效，序列化副本用于审计。VerificationResult 是状态对象，不是签名 proof；不能由审计 JSON 重建核验授权。规则二的样例专属映射、四规则口径及金额显示精度见架构文档。

未核实解释、定位、缺口与失败状态保留，不用模型补写为事实。旧预检的坐标金额复核不能升级为 v2 独立核验；历史 JSON 不补写未实际执行过的验证。

## 5. 运行归档、配置与外发

- 每次运行使用唯一 run_id，报告与记录共用标识；任务状态和评测用独立 job_id、evaluation_id。
- 归档输入来源与哈希、代码版本/快照、提示词与规则版本、模型标识及参数、调用过程、计算与核验、错误和输出。无 Git 时记录可核对的源码哈希，不虚构提交号。
- 模型记录包含实际请求/响应、时间、用量和关键结果；记录前移除密钥、鉴权头等敏感信息。不能只记录提示词与随机种子就声称在线结果完全可复现。报告等下游输出也须防止夹带凭据。
- .env.example 不含真实凭据。Web 保存的 .env.model 是被 Git 忽略的本机明文文件，采用原子替换并尽可能收紧权限；不修改原 .env。前端只短暂持有输入密钥，经本机代理发送，不回显或持久化已保存密钥。加载、回退、损坏配置与空密钥沿用规则以 README 为准。
- “测试连接”会发出真实供应方请求，审计进入唯一 model-connection-test 运行目录；它不保存草稿、不发送年报。不能把字段齐全称为连通性已经验证。
- 原始材料、索引、计算与运行记录保留本地。后端仅外发公开或获准的必要片段，记录文档和页码；不上传整库、评测答案或事后处罚材料，不开放任意互联网检索。现场联网范围按比赛环境落实。
- model_investigation 的候选调查与最终评审结果均保留模型观点身份。旧归档无 model_review 时兼容；deterministic/M3 不调用模型。模式细节见架构文档。
- 复现区分重新计算与历史回放；不得把读取已有报告描述为实时分析。历史某次获得的凭据访问授权不自动扩展为新任务的授权。

## 6. 样例与评测


- data/samples/ 用于演示输入；案例清单、人工期望和标签进入 evaluation/cases/。
- 对真实数据、脱敏数据和人工构造数据分别标明性质及处理方法。
- 历史案例分析只使用截止分析时点已公开的材料，记录材料可用时间。
- 后续处罚信息、事后调查结论及人工答案只用于评测，不能进入该案例的历史分析检索范围。
- 对照方案使用相同输入和评测口径；记录样本范围，避免用少量演示案例声称已验证泛化能力。
- 未发现处罚或公开舞弊记录的公司不能直接标记为“已确认无舞弊”，需明确对照样本的标注依据。
- 样本单位为“公司 + 报告期”；标签另附报告类型、受影响文件、处罚所认定的财务事项、受影响期间及标签截止日。只有明确涉及财务虚假记载等事项并能映射到相关财报的认定才作为相应正例依据；一般违规处罚不直接当作财报舞弊标签。
- 区分分析材料截止时间与评测标签观察截止时间。例如后续处罚认定早期财报存在问题，标签对应受影响的早期财报，处罚文本只进入隔离的评测标签区。
- 开发、验证和测试以公司隔离，并设置报告披露时间边界；同一公司的相邻报告期、同一财报的修订版本及衍生片段不得跨集合泄漏。训练集内才能拟合预处理、采样或平衡处理，验证集用于规则与阈值选择，测试集锁定后不参与调参。
- 测试集尽量保留目标使用场景的类别比例；若另建正例富集的压力案例集，应分开报告。未确认对照与未知样本的处理、弃权比例和数据覆盖率必须随指标披露。


既有 M4 协议为 evaluation/verification_ablation_cases_v1.json，由 scripts/evaluate_verification_ablation.py 执行。其 clean 值由 agent 按 PDF 转录，未获人工复核；错金额、错单位、错年度/期间、错口径和无支持 Claim 是受控注入，不是处罚或舞弊标签。

该历史协议的已知案例分母为两个 clean 与五个注入案例；两个跨公司 provisional 案例只作未知状态对照，排除在准确率、拒绝率和覆盖率分母之外。不得为匹配新计划而改写历史统计。未来评测须版本化说明分母及未知样本/弃权口径，单独报告总体覆盖；新计划与历史协议不同不等于旧实验已经按新协议完成。

## 7. 临时文件与清理


临时文件统一放入 tmp/<task_id>/，就近归属于相关模块；公共临时位置为 artifacts/tmp/<task_id>/。正式样例、报告和复现证据不依赖这些目录。

临时内容转为长期资产前，应整理命名、来源、文档和相关检查，再迁入对应正式目录。已有 tmp/、任务子目录及其中临时文件默认保留，任务结束不主动清理。

仅在用户明确要求清理时，先核对归属和绝对路径范围，再清理获准且确认不再需要的内容；不删除未知任务内容、用户资料或必要证据。自动化清理机制尚未实现，执行清理时由协作者按 AGENTS.md 完成核对。
