本文是当前已启动 goal 的实施任务书，不替代 [AGENTS](../AGENTS.md) 或[产品交付路线](product-delivery-roadmap.md)。第 8 节按实际审阅结果维护；未通过的目标不能作为功能已实现或验收已通过的说明。

本任务启动时，用户要求计划、文档和审阅由主控亲自完成，不交给当时的执行模型编写。后续协作遵循当前 [AGENTS](../AGENTS.md) 的角色分工和[开发说明](development.md)，本任务书不再固定执行型号或要求每阶段重建代理；既有验收保留当时的执行身份。

## 2. 目标与边界

用户需要一个可用的年报分析产品：上传文本型年报后，能较快看到基础结果，随后持续看到有来源的公司特有线索；知道当前处理到哪里、哪些地方失败，并能保留成功结果、补跑失败部分。结果应回答“发生了什么、为什么值得关注、原文在哪里、还缺什么”，而不是要求用户理解内部模块和数十个批次。

本 goal 必须完成以下软件结果：

- 升级代码后不再让旧 API 与新分析子进程混跑，已有合法报告能够恢复查看。
- 基础核验、试行规则、AI 发现和评审分层保存、分层展示；局部失败不抹掉其他可信结果。
- 长任务支持增量结果、明确预算、取消或中断后的保存，以及失败批次续跑。
- 从大量分批观点形成问题级归并和跨章节取证，重要事项不被简单的前若干条截断丢弃。
- 面向用户收敛为一个“分析年报”主入口，明确是否启用云端 AI。
- 海天与用户提供的茅台失败案例完成修复后的真实 Web/API 验收，性能达到下文目标或诚实保留未达标项。

不在本 goal 中扩展 OCR、向量库、第二套智能体编排、模型训练、登录、云部署、季度 Web、CI 或全站视觉重做；不重建初赛材料、视频、历史 ZIP/PDF。保留 React/TypeScript/Vite、FastAPI、LangGraph 和本地统计计算方向。既有模块优先复用，确有必要的拆分必须服务本任务。

“任意年报”在本任务中意味着：对范围内的新公司文本 PDF 能尝试处理、按真实内容发现问题，失败或缺证有明确结果，不硬编码公司答案。它不意味着承诺所有 PDF 版式都可正确抽取，也不意味着所有比较都必须有数值或必须发现风险。

## 3. 开工与证据定位

先读 AGENTS、README，检查 Git 状态，再读本文件、[架构](architecture.md)、[数据规则](data-policy.md)、[全文发现契约](annual-discovery.md)、产品交付路线及[开发说明](development.md)。涉及评测时另读 [evaluation/README](../evaluation/README.md)。无需遍读所有旧 brief。

本次审阅的代码身份、失败任务、调用统计、新旧读取器对照及测试记录集中在[年度分析可用性审阅记录](verification-history.md#annual-analysis-recovery-review)，下一会话先核对当前版本是否已变化。该段列出的运行目录是本机证据，干净克隆不一定包含；缺少资料时不得编造复现结果。临时辅助脚本不是正式功能的依赖。

已经建立的诊断起点如下，实施前确认是否仍成立：

| 问题 | 已知依据与实施含义 |
| --- | --- |
| 新旧后端混跑 | 启动日志、代码更新时间及旧读取器离线对照共同支持这一诊断。旧读取器拒绝新版发现层，当前读取器能读取三份报告。不是要求通过删除版本检查来接受未知结构，而是保证运行版本一致。 |
| 已有结果被失败任务挡住 | 海天集成任务已有基础结果、大量发现和完成的评审；旧 job 仍是失败状态。应恢复合法报告可达性，不先触发新模型调用，也不回写旧 job 为成功。 |
| 长任务成本与失败放大 | 两个 AI 模式都包含全文扫描；连续连接失败仍派发后续批次，重新分析会重跑全文。连接错误记录本身不能确定是服务商、代理、DNS 或其他网络原因。 |
| 线索多而综合不足 | 最终评审只接收按优先级排序后的有界前缀；同类事项的不同措辞未充分归并，后部附注问题可能被前面的重复项挤出。 |
| 跨公司核验不足 | 茅台有基础事实但缺少可比性依据，无法生成已确认比较；M3 某项语义映射只支持海天特定版式。应补通用证据提取和清楚的弃权结果，不能硬套海天证明。 |
| 模式难以理解 | 四种选择主要是内部能力的组合；两个 AI 入口使用同一全文扫描流程，区别主要在是否附加试行规则。 |

开工保留用户已有未提交文件，尤其计划书 Word 的删除/另名文件和用户提供的茅台 PDF。以当时 Git 状态为准，不把本文的历史描述当作可恢复、可删除的清单。

## 4. 产品与实现约束

### 4.1 用户看到的主流程

1. 选择本机样例或上传文本 PDF，确认公司及报告期，点击“分析年报”。
2. 以清楚的开关或选择说明是否启用云端 AI。未启用时，名称和结果说明明确为基础数据核验；不得声称做过公司特有问题发现。未配置时可进入设置，也可继续本地分析。
3. 基础结果准备好即显示。AI 工作期间显示实际阶段、已覆盖范围、已保存发现、预算与可执行的恢复操作。
4. 主报告先展示少量经过归并的重点问题及其依据；完整问题列表、原文和处理明细可展开。没有合格问题时说明范围及缺口，不为了填满页面凑数。
5. 部分失败时直接保留可用结果，并提供“补跑失败部分”；全量重新分析是不同操作，要说明其调用范围。

M3 放在高级选项，旧预检保留在历史/兼容入口。后端原四种 mode 及旧归档仍兼容；不得把历史未执行的全文扫描或核验补记为执行过。

### 4.2 可信边界

- 整份报告的主体身份、源文件 SHA 或来源归属不可信时，仍整体拒绝。某个可选分析层失败时，只展示其他独立通过检查的层；不得通过降低来源或引用检查来实现“可见”。
- 已核验事实、计算、模型观点、待核查事项保持分层。模型引用、模型自审或另一轮模型评审都不是独立事实/因果核验。
- 原 PDF、旧 job、旧报告、旧调用审计不改写。合法旧报告的恢复用只读可用性投影或另存恢复记录表达，保留当时失败事实。
- 新运行的部分结果应进入正式运行产物；最终完成前不伪装成完整报告。API、页面、历史列表和导出对部分状态使用一致契约。
- 新发现层仍有明确的文字/图像范围、覆盖与遗漏账。优化不得悄悄只读前部、只查固定关键词或把失败文本计作成功处理。

## 5. 实施阶段

主控可按实际代码调整阶段内部拆分，但不能跳过下列交付结果。每阶段先给出简短实施策略和验收条件，再派发具体文件归属；审阅实际差异和证据，失败就在该阶段修正。通过后再做本地 commit 并进入下一阶段，不合并用户原有改动。

### 本轮实施约定

- **R1** 先以启动时捕获的进程源码身份和协议版本拒绝混跑，再用严格归档读取器的只读可用性投影恢复失败任务的报告入口。报告可读与原任务失败分别表达，历史状态和来源检查不改写。
- **R2** 基础报告先归档，批次通过结构与引用检查后保存正式检查点；取消和硬截止以可终止的执行边界落实，不能只设置 socket timeout。续跑绑定源、模型、提示词、解析与批次计划，产生新 run 和父子关系；成功批次及已完成的独立阶段优先复用，禁止跨身份缓存。
- **R3** 在同一原文范围比较请求正文、元数据和解析开销；优先压缩重复定位元数据和复用本次解析，不以关键词过滤替代全文。覆盖账仍按原文字符、页面和批次记录成功、部分、失败、未尝试及遗漏。默认主报告截止与后续补跑预算分开展示。
- **R4** 全部合格发现先进入可审计的事项分组，再将问题摘要送入有界评审；每项保留原 finding ID、支持/解释证据和缺口。补证限同源年报并保留定位，不把模型优先级视作概率，不以条数为目标。
- **R5** 普通入口只需选择年报及是否启用云端 AI；M3 留在高级选项。基础核验、公司问题、覆盖与恢复操作按实际阶段展示，旧 mode 和归档语义不变。
- **R6** 先通过全部离线故障关卡，再启用两份已授权材料的新在线 Web/API 验收；独立对照仅本地读取。原文对照由 agent 执行时明确其性质，真人复核仍是外部关卡。

真实请求预算预分配为两份年报各最多 30 次首次处理，共 60 次，另留 20 次失败续跑和必要补证。它是规划额度，不是实测调用数；R3 必须用最终离线计划核对扫描、调查、归并/补证和评审的逐阶段需求，正常流程明显不够时先优化，不启动必然超额的在线运行。累计 80 次为跨公司、跨 run、跨进程的共同上限：网络失败、重试和连接测试均纳入联网前持久化记账，旧审计回放与 mock 分开统计；不安排独立付费连接探测，以实际验收请求验证服务。首次运行未完成的批次只由续跑尝试，不反复全量重跑。最终计数、证据与剩余额度由验收记录维护。

### R1：恢复版本一致性与已有报告访问

**关注文件：** [start.ps1](../scripts/start.ps1)、[API 入口](../backend/src/finagent/api/app.py)、[年度任务](../backend/src/finagent/api/annual_analysis_jobs.py)、[归档读取](../backend/src/finagent/api/annual_report_read.py)、[历史索引](../backend/src/finagent/api/annual_analysis_history.py)、[年度页面](../frontend/src/pages/AnnualAnalysisPage.tsx)。

**实施结果：**

- 区分正在运行的 API 身份/构建版本、磁盘代码和 CLI 的协议能力。指纹须代表进程实际加载的版本，不能每次读当前磁盘文件就冒称为运行版本；仅 OpenAPI 名称或 `annual_discovery_supported=true` 不足。
- 已识别本项目的旧进程采用安全重启或明确拒绝新任务并给出可操作的更新路径；未知端口占用不得被终止。活跃任务的保存、中断和重启状态不得混淆。
- 任务失败但报告目前可安全读取时，历史列表、job 页面和按 run 查看均能进入报告，明确“原任务失败，现归档可读取”，不重写原始状态。
- 错误说明区分执行失败、模型失败、归档不兼容和来源校验失败。

**验收：** 离线模拟旧 API/新 CLI 组合，在付费任务开始前发现不兼容；同版本正常运行。审阅记录中的三份归档只读可达，海天已有发现和评审可见；来源篡改仍拒绝。刷新失败 job 后有明确报告入口。无模型调用恢复已有结果。

**关卡：** 先通过此阶段，才进入新的 AI 运行改造。不要以“重启过一次”替代持久修复。

### R2：部分结果持久化与失败恢复

**关注文件：** [年度 CLI](../scripts/analyze_annual.py)、[调查附加层](../backend/src/finagent/reports/investigation_append.py)、[发现引擎](../backend/src/finagent/agents/annual_discovery.py)、[调用审计](../backend/src/finagent/audit/audited_chat.py)、[连接器](../backend/src/finagent/llm/chat_completion.py)、年度任务/报告接口及其前端类型。

本轮方案要求正式基础产物、已验收批次检查点与最终报告分开标识；部分读取通过受控 API 投影，不把计数进度文件当报告。取消和续跑使用独立操作，续跑创建新的 job/run 并保留父记录。真实请求的共同额度在联网准入前持久化占用，跨线程和子进程不能各自拿到一份额度；连接测试与其它直接调用也走同一请求计账边界。真实阻塞调用采用可终止边界，截止和取消后停止新准入并有界结束在途工作。提示词、解析器和批次计划发生不兼容变化时明确拒绝复用，不能为提高命中率降低绑定要求。

首个模型请求前保存的基础快照须包含源、完整任务模式、模型、提示词、解析与计划的恢复绑定及未完成 AI 阶段；在固定候选调查期间取消也应能识别待补工作，不等进入全文扫描后才建立绑定。已完成的独立调查及时保存。不可重试的配置、鉴权和准入错误停止后续派发；连续可重试故障按实际请求尝试累计，不能因分属不同批次漏计。

服务重启后，关闭旧任务准入并不等于旧报告写入者已经退出。管理器须在有界等待内确认原 CLI 已停止，再公布可续跑能力；只能观察本服务实际创建进程的创建身份或读取精确的停止确认，不凭裸 PID 终止未知进程。无法确认时，可信部分报告仍可只读，续跑明确暂不可用。父运行在子任务启动后不再变化；旧 CLI 已保存的失败事实和已封存最终报告均保留。

用户取消同样须确认所属写入进程退出后才追加终态检查点；终止命令失败或退出未确认时，保留可读报告并暂缓续跑，不把尝试停止写成已经停止。本机心跳更新须兼容 Windows，更新失败应安全收束任务并保留明确原因。

Windows 上正式报告的原子替换遇短暂文件占用时须有界处理，不能覆盖写入正式 JSON 或无限重试。持续发布失败时保留最后可信检查点并明确归档失败；CLI、job、快照和导出不得将尚未封存的运行中快照描述成成功完成。模型阶段已完成与最终报告已耐久发布分别确认。

已完成的独立调查或评审复用须能追溯原成功调用，子运行本次调用记为零，严格读取、页面和导出仍能表达合法完成状态。后续再次续跑不能因原审计丢失或本次核验时间变化而重复调用；来源、模型、提示词及恢复绑定仍须一致。评审复用以实际请求的语义输入为准，事实、发现、调查解释、覆盖或缺口改变时重新评审，不通过忽略业务内容制造复用。

执行与恢复契约须独立版本化，旧提示词版本和旧归档的严格规则继续保留。本次准入、本次耐久响应、复用批次、父子累计及整个 goal 的共同额度分别计量；合法空发现或语义检查全部拒绝的耐久响应不能计作合格发现。重试记录按真实审计目录及尝试序号对应，不能因一个批次共用外层审计编号而拒绝合法重试，也不能允许跨批次冒用记录。账本缺失、损坏或部分表结构缺损须停止外发，不得修复成空计数。续跑身份包含原请求的完整任务模式，不能只绑定“年度”报告类型；父批次已有合格发现，在子任务重试失败或返回空发现时仍须保留。检查点并发写入、序号发布和最终封存应保持一致，浏览器不得因同秒更新或读取并发漏掉最后一份结果。清单、快照指针和封存记录分步发布时，中途退出后仍须能严格读取已保存结果；未封存结果继续作为部分结果，不冒称最终完成。

**实施结果：**

- 基础报告和每个已验收批次及时持久化；前端通过受控契约读取安全的部分结果，不读取任意审计文件。
- 实现用户取消、实际可执行的总时限和终止后的收尾。网络/socket timeout 不等于硬墙钟截止；不能无限等在途线程后才允许结束。保留已成功批次，不把计数进度当结果保存。
- 对连续连接失败、限流和可重试服务错误设计有界退避及停止派发机制；不可重试配置/鉴权错误尽早停止。保留脱敏错误类别，便于说明原因。自动重试必须计入请求预算。
- 续跑复用已通过检查的批次，只尝试失败/未完成项。缓存与续跑绑定源 SHA、解析/分批计划、模型与提示词/契约版本；不同源、不同模型或不兼容计划不得误复用。
- 续跑建立新的尝试记录及父子关系，保留原运行事实；合并后的覆盖、调用量、来源和导出能追溯到各次尝试。
- 部分失败仍可生成有限主报告；最终评审失败不隐藏基础结果和有效发现。

**验收：** mock 覆盖部分成功、全失败、断网、限流、取消、硬超时、服务重启和续跑。成功批次不被重复调用；换源/换模型会拒绝错误复用；取消后不再准入新调用；已有结果在重启后可恢复。错误引用不因恢复流程而通过。

**关卡：** 故障模拟与归档契约通过后，才允许用真实服务验证恢复行为。不得用几十次真实失败请求调试故障逻辑。

### R3：控制耗时与请求规模

**关注文件：** [全文上下文规划](../backend/src/finagent/retrieval/annual_discovery_context.py)、发现引擎、调查附加层、年度 CLI，以及 R2 新增的预算与阶段结果契约。

本轮选择批内短别名和共享来源头压缩重复元数据；完整证据 ID、页码、文字块、字符位置、坐标和原文仍在本地绑定。别名须有无歧义的批次命名空间，输出只能映射回本批片段，再执行原引用校验。先保持已有原文与序列化上限，用实际新提示词和执行请求测量；候选原型测量不代替最终请求测量。提示词、解析器、计划和执行契约分别版本化；R2 及更早归档仍按其原版本严格读取，不跨版本续跑。

预算实施方向为从 job 实际 running 起点计算整份 300 秒，软工作截止预留本地发布与有界退出时间，基础解析和核验计入其中；排队另记。首次任务总准入上限 30，续跑任务上限 20，均受整个 goal 剩余额度约束。扫描、固定调查、后续归并/补证及评审分别设置实际准入和阶段截止；自动重试也占用对应额度。阶段耗尽保留结果和缺口，并给其他阶段留额度；取消、不可重试错误或整份截止则收束整个流程。具体分配须以最终离线计划审阅为准，实施与故障验收通过前不作为性能已达标的说明。

**实施结果：**

- 分别计时上传、解析、核验、上下文规划、排队、各模型阶段、首个可读结果和最终归档；统计请求尝试、响应、用量及并发。
- 针对真实瓶颈优化碎片数量、重复元数据、上下文组织与重复解析，不把主要工作消耗在无意义的切片开销。结构化章节/表格上下文应保留追溯定位。
- 全文低成本覆盖与重点事项深入核查可采用分层策略；主控先说明覆盖账、预算和跨章节信息如何传递，再落代码。目录、页眉等重复内容可以明确识别和记账，不能偷偷丢掉正文。
- 模型输入与输出预算匹配任务；旧常量如需调整，同步解析器、API/导出契约和测试。不得只增加并发或把等待上限调大就声称性能修复。
- 用户能看见默认分析预算和深度补充的范围。预算耗尽后形成明确的部分结果，不以空缺口页充作可用分析。

**验收：** 使用相同输入比较改造前后各阶段耗时与请求规模；mock 验证预算上限和调度，真实服务按第 6 节计时。范围减少、覆盖方式变化和重用缓存必须披露；不能只用缓存运行证明首次分析提速。

### R4：从分批发现形成公司问题清单

**关注文件：** 发现引擎、[最终评审](../backend/src/finagent/agents/annual_review.py)、调查附加层、[运行时提示词目录](../config/prompts/)、报告类型及结果页面。

**本轮实施方向（已审阅通过）：** 全部合格 finding 先形成本地问题候选和逐项处理账；本地仅合并完整观察、关注理由、核查动作与引用均等价的明确重复，共同引用不能证明同一事项。云端语义归并按完整候选集分片，每项必须有保留、合并、排除及理由，非法或遗漏成员使整片回退为待处理候选。已接受分片与未完成候选都进入完整问题视图；跨片全局关系尚未闭合时明确未完成，不以局部无重点代替全局结论。

主控已接受具体合同并完成核心实施审阅：当前合格发现的全局归并闭合与原文扫描完整性分别表达；多个语义分片须再验证全部问题/成员及排除账的全局关系。新 review_v3 完整请求上限为 24000 字符，保留全部问题及处理路径；部分扫描或待处理归并也可获得有限评审，但“范围内未发现重点”另要求完整覆盖、全局闭合且无缺口。耐久响应、合格输出、本次准入与零调用复用分别计量，审计路径和当前调用计数不替代业务语义绑定。初始快照先声明等待发现，随后逐片保存；具体已实现状态仍按下表与验收记录读取。

当前冻结候选中，事项归并、跨片关系及补证角色共用无损 typed 编码，外层协议为 `annual_issue_input_compact_v1`，内层业务 schema 与完整候选、成员、原文、引用及角色不变；完整语义对象仍逐字归档。编码版本进入执行绑定，生产请求、尺寸准入、审计重建、严格读取与续跑采用同一序列化规则。旧 review_v2 与旧 v3/v4 流程不套用新编码。此次方向解决重复结构开销，不增加请求上限、阶段额度或自动重试；真正超过预算仍保留明确 pending。源码和单元审阅不代替实际管线及恢复验收，阶段状态仍以验收记录为准。

当前冻结候选的最终评审采用显式用途投影，再对投影对象无损编码，仍保留 review_v3 业务输出契约及 24000 字符上限。完整基础报告、核验记录、坐标和事项归档保留；模型输入可以省略明确证据路径内的几何坐标、抽取方法、空的页码别名/历史区域/相邻文本及 Claim 核验时间，但必须保留来源标识、SHA、PDF 页、表头/行列/单位原文、全部金额/期间/币种/口径、检查结果、冲突、理由、限制、完整问题/成员/补证角色和范围缺口。非空相邻文本不得省略。投影仅作用于列明的证据结构路径，不按任意同名键递归删字段。核验池的内部指针可使用无碰撞、同步引用的短别名，输出允许的业务 ID 保持原值。

评审专用新外层协议为 `annual_model_review_v3_compact_v4`，支持完整对象/列表包装、列向量、精确重复列表和非布尔整数节点标记；禁止子串替换、私用区、压缩载荷或截断。它与事项阶段的 `annual_issue_input_compact_v1` 分开，事项编码不随此项改变。生产请求、预算、审计及严格读取必须共享同一投影/编码/Chat body 构造；解码只承诺精确还原投影对象，不声称恢复被省略的机械元数据。复用签名仍核对完整投影前业务及既定有效时间归一化规则，缺失/无效时间状态和业务变动不能因投影而忽略。新协议及提示词字节进入恢复绑定，不改写旧归档。尺寸原型只支持本次实施方向，正式实现、严格读取、实际调用边界与故障恢复须重新验收。

补证从同源、同 SHA 年报的经营讨论、报表和附注定向检索，独立保留页/块/字符/坐标。相关上下文、模型认为可能解释、尚待确认分别表达；关键词命中不自动构成解释或反证。归并及补证共用既定 annual_issue_grouping 准入类别、首次 8 次/续跑 2 次及默认 35 秒阶段预算，自动重试同样占账；最终评审独立保留 2 次额度，不另开隐藏预算。

当前候选采用新 execution_v5 流程绑定 annual_issue_pipeline_v1、新归并提示词及 annual_review_v3；全文请求仍沿用 R3 的 plan_v3/discovery_v3。新评审接收完整问题集合或完整分层处理路径，尺寸或预算不足则保留全部候选及明确 pending，不再按模型 priority 截前十二条。旧 v3/v4 精确读取和 review_v2 输入/审计重建保持原语义，禁止跨流程续跑或补记旧报告已归并。114 个冻结文件的受影响回归、前端构建、严格恢复能力（6/6）、四例受控 CLI 语义专项、完整故障矩阵与恢复运行验收（9/9）及浏览器端到端验收（21/21）均已通过验证。

**实施结果：**

- 将同一事项的不同措辞和多处引用归并为可追溯的问题，保留支持证据、反向证据、缺口与原发现关联。
- 所有合格发现进入可审计的分组/筛选/分层归并路径。最终输入可以有界，但不能仅“按模型优先级取前十二条”就代表全局综合；合并、省略及其原因要可查。
- 对重点问题回到同源年报定向补证，允许关联前部经营讨论、财务报表和后部附注；跨批联系不能只靠模型想象。
- 重点列表按可解释的业务相关性、证据充分程度和待核查价值排序，不把模型自报 high 当风险概率。
- 允许合法空发现。清洁披露、一般经营安排、格式缺项或目录标题不能自动变成风险。数值复述必须来自可追溯事实/计算；提示词和解析器作为行为变更共同审阅。

**验收：** 构造不同公司/内容的独立 PDF，包含后部附注独有重要事项、重复表述、互相解释的跨章节材料及清洁对照。重要后部事项不能被重复的前部发现挤掉；合并后的每条证据可定位；同源补证范围明确。固定批次/条数不作为发现数量目标。真实案例另外进行原文对照，agent 审阅不冒充真人金融复核。

当前 R5 软件范围已完成：普通入口映射既有四 mode，重点概览不丢弃完整发现/成员账，基础财务对照前置，来源缺省角色兼容仍保持严格校验；原生增量经独立审阅后回收，并完成当前构建及实际桌面/窄屏浏览器演练。AI 路径只使用原创模拟输入和 loopback 服务，真实海天材料仅本地基础分析或旧失败归档只读；没有新的真实供应方通过结论。具体证据见[R5 验收记录](verification-history.md#annual-analysis-recovery-r5)，非金融用户理解试验仍待真人执行。

## 6. 性能、预算与真实验收口径

下列是本任务建议采用的工程验收目标，不是当前测量结果或供应方 SLA。下一会话采用本任务书实施时按此计量；确实无法达到时列明未达标原因，不事后调大数字来制造通过。

| 项目 | 目标与计量 |
| --- | --- |
| 基础结果 | 同机代表年报，从 job 被接受到基础结果在浏览器可读不超过 15 秒；上传耗时另记，排队时间另外展示且不能藏掉。 |

| 完整处理 | 单独记录全文覆盖、全部计划是否处理完和最终评审是否完成；不能把“可用主报告时间”写成“全文完成时间”。后续深度处理或续跑须有独立、可见的有限预算。 |
| 故障收尾 | 实现有限硬截止及可控取消，截止后保留正式部分产物；网络或模型故障不能造成无限等待，也不能清空已完成结果。 |
| 调用预算 | 真实请求尝试累计不超过用户明确授权值；默认启动指令为 80 次。响应失败、自动重试、测试连接、补证及评审都计入。token/费用只有供应方提供或价格已核实时才报告，不凭尝试数推算金额。 |

真实运行前先用离线计划估计两家公司各阶段调用数并预留续跑额度；预算明显不够时先优化软件，不带着必然超额的方案开始调用。无需为故障模拟消耗真实请求。若服务不可用或额度不足，完成其他独立工作，停止继续外发并明确在线关卡未通过；不反复试到偶然成功再隐去失败。

真实材料范围及用途按[数据规则](data-policy.md)。默认启动指令只授权两份指定材料的在线验收，第三份对照保持本地；额外外发须有明确新增授权。模型配置、密钥和资料使用权限不得由旧会话记录推定。

## 7. 最小验收矩阵

| 场景 | 必须证明的结果 | 方式 |
| --- | --- | --- |
| 旧 API / 新 CLI / 前端版本变化 | 新任务前发现不兼容；同版本可运行；不终止未知进程 | 针对性测试与启动演练 |
| 三份既有归档 | 新代码可读；旧失败事实保留；无新模型请求恢复合法结果 | 只读 API、浏览器、前后哈希 |
| 基础模式与旧模式兼容 | 基础模式零模型调用；旧四 mode 与旧预检可读，模式含义不篡改 | 测试、调用哨兵、浏览器 |
| 成功 / 部分 / 全失败 / 空发现 / 非法响应 | 状态和覆盖准确；合格结果保留；不把非法来源或引用放行 | 单元及集成测试 |
| 取消 / 超时 / 断网 / 限流 / 服务重启 | 有界结束、已有结果可恢复、失败类别可理解、无失控派发 | 可重复 mock 故障注入 |
| 失败批次续跑 | 不重调成功批次；来源/模型/版本绑定；父子审计及覆盖合并正确 | 调用计数断言与浏览器 |
| 后部独有事项 / 重复 / 跨章节解释 / 清洁对照 | 全局归并不漏掉关键后部输入；不凑数；每个问题可追溯 | 原创受控材料与原文对照 |
| 海天与茅台新运行 | 可用报告、实测耗时、明确缺口、错误不拖垮整份结果 | 授权后的真实服务 + Web/API |
| 独立对照材料 | 不依赖两家公司固定答案；支持或弃权均有证据 | 本地离线对照，注明样本性质 |
| 页面与导出 | 上传、刷新、路由、历史、证据、续跑及三格式导出一致 | 桌面/窄屏真实浏览器 |

每阶段执行与改动相称的检查。最终对最终代码运行后端完整套件、前端 typecheck/build，以及本表要求的浏览器主流程；检查实际跳过原因。通过后不无理由重复跑完整套件。后续又改到相关契约时才重跑受影响检查。没有环境或依赖时如实记录，不自行安装绕过项目规定。

正式证据按 AGENTS 写入唯一运行/评测目录，记录输入哈希、实际代码/进程版本、模式、预算、调用尝试、耗时、状态和限制。测试不依赖临时目录或真人密钥；受控错误与真实案例分开。外部资料许可不明确时，公开提交件不含其原文、整页图或调用请求/响应。
