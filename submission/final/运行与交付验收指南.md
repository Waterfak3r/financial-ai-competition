# FINTRACE 运行与交付验收指南

本指南用于在 Windows x64 本机复现随附原创样例，记录源码包、环境、运行和导出证据。它不是另一台电脑、竞赛现场网络/API、真人评测或易用性试验的通过证明；相关外部关卡列于第 7 节。项目当前软件基线与正式证据入口见[证据索引](evidence/README.md)。

## 1. 校验并解压源码包

从项目交付目录同时取得源码 ZIP、ZIP 外 `.sha256` 和 `.manifest.json`。三者的 package ID 应一致。先在 PowerShell 中核对下载文件与 sidecar：

```powershell
$PackageId = '<package_id>'
$PackageDirectory = 'D:\deliveries\artifacts\packages\' + $PackageId
$PackageZip = Join-Path $PackageDirectory ($PackageId + '.zip')
$ChecksumFile = Join-Path $PackageDirectory ($PackageId + '.sha256')
$ExpectedSha256 = ((Get-Content -LiteralPath $ChecksumFile -Raw) -split '\s+')[0].ToLowerInvariant()
$ActualSha256 = (Get-FileHash -LiteralPath $PackageZip -Algorithm SHA256).Hash.ToLowerInvariant()
if ($ExpectedSha256 -ne $ActualSha256) { throw 'ZIP SHA256 不匹配；停止解压和运行。' }
```

保留同目录的 manifest 作为 package ID、source commit/tree、受测环境及清单边界记录。构建器可对包目录执行额外校验：

```powershell
python scripts/build_final_source_package.py --verify $PackageDirectory
```

该命令要求在已取得源码树的项目根目录运行；它校验 ZIP、外部清单、runtime lock、许可文本与受控样例 manifest。源码包不含 Git 元数据、Python/Node 运行时、已安装依赖、`.env.model` 或用户材料。若 hash/manifest 校验失败，停止并保留输出，不尝试修改 package 或以不匹配文件继续。

完整解压后进入固定 ZIP 根目录 `FINTRACE_SOURCE`。本指南后续安装、启动和 CLI 命令均从该源码根目录执行；在新开的 PowerShell 窗口中也应先切换到这个目录。

源码包的正式构建与排除规则见[源码包说明](../../docs/final-source-package.md)。该说明中的精确 runtime lock 仅适用于 Windows x64 / CPython 3.14.3。

## 2. 准备并启动本机应用

按仓库根目录 [README 启动说明](../../README.md)准备 Python、Node.js 和前后端依赖。若要复现已登记的源码包 runtime 环境，限定 Windows x64、CPython 3.14.3、Node.js v24.14.1（本次随包测试的 npm 为 11.11.0）；该 Python runtime 锁不适用于其他平台或版本。源码包不含依赖，因此在源码根目录按以下顺序安装：先用 CPython 3.14.3 创建 `.venv`，按精确 runtime 锁安装版本，再以 `--no-deps` 注册本地后端项目以避免依赖下限重新解析，最后用前端锁文件 `npm ci`。

```powershell
$PythonBase = (Get-Command python.exe -CommandType Application).Source
if ((& $PythonBase --version) -ne 'Python 3.14.3') { throw '请将 PythonBase 指向 CPython 3.14.3。' }
if ((node --version) -ne 'v24.14.1') { throw '请使用已登记的 Node.js v24.14.1。' }
if ((npm --version) -ne '11.11.0') { throw '请使用已登记的 npm 11.11.0。' }
& $PythonBase -m venv .venv
$Python = (Resolve-Path '.\.venv\Scripts\python.exe').Path
& $Python -m pip install -r .\backend\requirements-final-win.txt
& $Python -m pip install --no-deps -e .\backend
Push-Location .\frontend
npm ci
Pop-Location
```

可用 `& $Python --version`、`node --version`、`npm --version` 记录实际环境，再按仓库根目录 [README 启动说明](../../README.md)运行 `start.bat`，等待本机 Web 页面打开。此流程使用 deterministic 年度分析和季度本地 CLI，不需要模型供应方配置。保持模型功能关闭；不要为本指南调用“测试连接”，该操作会发送真实供应方请求。年报原文只使用 `data/samples/annual/` 中允许分发的原创模拟 PDF。

若启动或分析失败，保留终端输出、时间和已产生的 job/run ID，先检查包校验、依赖、端口与输入 SHA；不要把缺失值填成 0，不要编辑归档来掩盖失败，也不要用真实年报替换许可清楚的演示样例。

## 3. 上传原创年度样例并创建新任务

年度演示文件为 `data/samples/annual/sim-annual-001-2025.pdf`，样例 ID `SIM-ANNUAL-001`，虚构公司“澄湾云算股份有限公司”，2025 年。其 SHA256 应为：

```text
f193e7a497fe483d3ab70b7bde2880f715ff1127b1d8b14cc3f4fda678ba0bf7
```

可在 PowerShell 复核：

```powershell
Get-FileHash -LiteralPath 'data/samples/annual/sim-annual-001-2025.pdf' -Algorithm SHA256
```

在 Web 页面选择“上传年报”，选择上述原创 PDF；公司代码填写 `SIM-ANNUAL-001`，报告年份填写 `2025`，再选择“标准分析”（`deterministic`）并启动新任务。不要使用“已有材料”入口：它目前展示的是未随公开源码包分发的真实年报。等待新任务进入 `completed` 后记录页面显示的 `job_id`、`run_id`、新分配的 document/upload ID、公司与报告年度、原始 PDF SHA256、运行状态和 `model_called`。每次任务 ID 都会变化；不要把索引中的历史 run ID 填作本次运行结果。

检查报告的事实、计算和 Claim 状态；确认候选/待核验内容仍有清楚的限制说明。可与正式年度运行索引中的同源样例进行内容核对，但当前新任务的输出和哈希应单独记录，不覆盖历史归档。仅此原创样例的既往确定性运行有 8 条事实及 8 项计算通过；本机新运行的状态以实际归档为准。

## 4. 导出年度报告并核对证据

在当前新 run 的年度报告页面下载 JSON、Markdown 和离线 HTML。逐项记录下载格式、文件名、文件 SHA256 和当前 `run_id`；检查 PDF 来源哈希、公司/期间/单位/口径、事实与计算状态和限制字段与页面归档一致。导出属于归档白名单投影，不应含原始 PDF、整页图、任意扩展字段、模型请求/响应或密钥。HTML 可以离线打开，也可以由验收人通过浏览器打印为 PDF；系统没有服务端 PDF 导出端点。

产品导出的格式和来源绑定规则见[年度报告导出说明](../../docs/annual-report-export.md)。缺少来源绑定或来源错配时，比较证据按契约降为未验证/错配并从导出移除；不要以页面上可见或 JSON 中出现字段作为独立核验通过的证明。

在报告中检查可用的已核验证据链接、原文位置状态及来源哈希。只把允许公开的原创样例与其安全导出放入分发目录；含原文副本的 `artifacts/runs/` 和归档报告保留本机，不公开上传。

## 5. 运行原创季度同比/环比样例

在 `FINTRACE_SOURCE` 源码根目录新开 PowerShell 终端运行：

```powershell
& '.\.venv\Scripts\python.exe' scripts\analyze_quarterly.py --year 2024 --quarter Q2
```

该命令读取 `data/samples/quarterly/source_manifest.json` 登记的四份原创模拟 PDF，不调用模型。记录新生成的 `quarterly-analysis-<UUID>`、`artifacts/runs/<run_id>/analysis.json`、状态和四份来源 PDF 的哈希。对照随附的原创季度 JSON 与 source manifest，核验来源观察、季度派生和比较层，而不是要求新的 UUID 与历史 run 相同。

基线示例有 24 个来源观察、9 个派生季度、6 个比较；营业收入和归母净利润的 Q2 同比、环比有依据，经营现金流环比基数为 −20,000 元，差额 +160,000 元，增长率弃权。金额都是人民币元、合并口径。若本次结果与样例 manifest 或上述输出状态不同，先保留本次归档并调查版本/输入，不手动修复 JSON。季度模块边界、公式与弃权条件见[季度分析说明](../../docs/quarterly-analysis.md)。

## 6. 验收记录模板与失败恢复

把本次验收原始记录放到新的 `artifacts/evaluations/<evaluation_id>/` 目录；交付前只将经过许可和脱敏检查的必要摘要迁入 `submission/final/evidence/`。收集基础环境时可运行：

```powershell
[System.Runtime.InteropServices.RuntimeInformation]::OSArchitecture
[Environment]::OSVersion.Version
& '.\.venv\Scripts\python.exe' --version
node --version
npm --version
```

每次复现应至少记录：

| 项目 | 记录值 |
| --- | --- |
| 日期与时区、操作者角色 | 现场填写；不记录不必要个人身份信息 |
| package ID、ZIP SHA256、source commit/tree | 读取已校验的外部 sidecar 与 manifest |
| 操作系统架构、Python、Node 版本 | 现场读取；不要填写推测值 |
| 年度样例 SHA256、document/upload ID、job_id/run_id/status | 从输入 manifest 与新归档读取 |
| 年度导出格式、文件名与 SHA256 | 对每个实际下载文件计算并登记 |
| 季度 run_id/status、source manifest 与来源 PDF SHA | 从新 run 和模拟清单读取 |
| 模型调用状态 | deterministic 流程应为 `model_called=false`；不保存密钥或模型环境值 |
| 错误与恢复动作 | 保留原错误和 run；写明重试使用的新 run ID |

遇到哈希不符、缺来源绑定、冲突、比较口径不明或验证 `insufficient_evidence` 时，停止解释该值并保留原始状态。修正可确认的输入问题后创建新 run，不覆盖旧报告。模型或网络错误不会取消基础确定性报告；本指南中不运行 AI。保存日志前删除本机路径、环境变量和值中可能存在的凭据。
