## 3. 来源与原始文件

- 仅使用公开、获授权或明确允许用于项目的材料，来源和使用条件随数据记录。
- 导入时为文档分配标识，记录原文件名、公司标识、报告类型与期间、发布日期、下载地址或本地来源、获取时间和文件哈希。
- 建议按公司和报告期组织原始资料，如 data/raw/<company_id>/<report_period>/<document_id>/，保留原始文件。
- 原始资料保持原样，解析、清洗和修正不得覆盖原文件。
- 同名但不同内容的文件按文档标识分开保存，并记录各自来源。
- 处理后结果引用对应 document_id 和原始文件哈希；需要纠正提取值时记录修正原因及依据。
- 第三方模型、代码和数据投入使用时补充版本、来源、许可证或使用条件、具体用途；不得把第三方成果描述为自主成果。

上述目录约定已用于这一份样例：原始 PDF 与 `source.json` 放在 `data/raw/603288/2024/cninfo-1222994233/`。`POST /v1/text-pdf-uploads` 只在 `data/raw/<company_id>/<report_year>/<document_id>/` 新建 `source.pdf` 与 `source.json`，并在平行的 `data/processed` 路径新建 `text_pdf.json` 与 `processing.md`。上传生成的来源记录标注公司和年度取自上传请求、未独立核实 PDF 内容。处理说明只记录生成的原始相对路径、SHA256、PyMuPDF 解析器及版本、未做 OCR，以及仅覆盖有可提取文字的文本型 PDF；不写上传原文件名、绝对路径或密钥。没有可提取文字的 PDF（含纯图片或扫描件）返回 422，并撤回本次新建文件。它不覆盖或修改已有原始资料。上传成功后仍需另调旧预检。v2 `POST /v1/annual-analysis-jobs` 可从已存 PDF 创建 deterministic 或 M3 筛查任务；创建前校验相对路径与符号链接、目录中的公司/年度/文档标识、相邻 `source.json` 的身份字段及 PDF SHA256。任务状态保存在 `artifacts/annual-analysis-jobs/<job_id>/job.json`，本地单进程同时运行一个任务、最多排队三个；服务重启后遗留的 queued/running 任务转为 `interrupted`。模型调查模式当前不支持。

## 4. 财务事实与证据

结构化事实需要同时保留：

- 文档标识、原始文件哈希、PDF 页序号以及原文页码（如存在）。
- 所属表格、行列位置或原文片段；具备定位条件时保留坐标。
- 公司、指标名称、原始文字和规范化数值。
- 报告期、时点或期间类型，年度、季度或累计口径。
- 币种、单位倍率，合并报表或母公司报表口径。
- 本期数、比较期数及是否追溯调整等上下文。
- 提取方式、处理过程以及人工修正记录（如有）。

财务计算先核对单位、期间和报表口径。缺失值不得直接当成零，口径冲突不得静默拼接。发现提取错误时回查原文，在处理后数据中修正并保留记录。

年度分析页面显示 PDF 物理页序号，并保留位置来源的状态：同源且通过独立核验的证据可进入白名单页图预览；仅由未核实提取结果定位的页码标为“待核实定位”，不提供独立核验证据页图入口。来源绑定、页码区域或相关事实不足以支持可靠定位时显示“原文位置待定位”，不根据印刷页码或相邻页面推测。

应收账款净额与存货净额的 v2 字段切片从海天 603288 的 2024 年报第 76 页“合并资产负债表”提取；合并净利润与营业成本从第 81、82 页“合并利润表”提取。利润表表列单位为元、币种为人民币，按 2024 年度与 2023 年度两个期间列出流量值；资产负债表列出相同两年的 12 月 31 日余额。四项字段均保留报告年/比较年角色、原始文档哈希和证据位置，并由独立核验重新读取原 PDF 检查金额、列、期间、币种与合并口径。构造 PDF 错误注入覆盖错金额、错年度列、错单位、错口径、错误比较角色和缺失信息。字段切片由 CLI 显式可选路径 `--with-m3-screening` 写入同一 run_id 的运行归档与报告；海天正式样例 `annual-analysis-5e7079fe-9ac9-4e96-85fa-1898f9177d21` 包含 10 条新事实及其独立核验。默认 M2 的字段数量和报告结构保持不变。利润表事实追溯状态保持 unknown。上述测试未将披露的非经常性损益合计当作扣非归母净利润。

扣非归母净利润 `net_profit_parent_ex_nonrecurring` 的 v2 切片直接来自海天 2024 年报 PDF 第 7 页“七、近三年主要会计数据和财务指标 /（一）主要会计数据”表，2024 年金额为 6,069,416,506.67 元，2023 年金额为 5,394,663,934.17 元，单位为元、币种为人民币。提取器先核对传入原 PDF 哈希与解析记录一致，再从原 PDF 字词坐标按 2024、2023、2022 年表头对齐行金额；同比百分比列位于 2023 与 2022 两个金额列之间，会被排除。独立核验器会重新打开原 PDF 并重新读取字词及坐标，不使用提取阶段坐标；构造 PDF 覆盖错误金额、错年顺序、把 12.51% 或 2022 金额当作比较期、错单位、错币种、错报表口径、缺少比较值/百分比列/目标行及源哈希不匹配。该表不是合并利润表，因此事实使用 `statement_type=key_financial_data`、`scope=unknown`；核验只能确认披露行、金额和期间，不能宣称合并报表口径已获证明。该字段的 `restatement_status` 为 `unknown`。规则二另有海天 603288 2024 样例专属语义映射：仅在核验器重新打开相同来源 PDF、重读物理第 7 页并定位完整原文“归属于上市公司股东的净利润”后，且该行 2024/2023 金额与合并利润表归母净利润逐年完全相等时，才签发当前进程有效的 proof。proof 绑定来源 SHA256、document_id、报告年、两年 key-data 与 parent facts 的 ID/normalized value，以及第 7 页重新定位区域；序列化结果只保留审计，不可用于后续进程筛查。该规则专属 proof 只支持此海天版式，其他公司或报告期间弃权；`scope=unknown` 不得自动视为口径相同。

`finance/m3_screening.py` 独立实现四条试行年度规则，精确使用 Decimal：合并净利润为正且经营现金流为负；归母净利润为正且扣非影响占归母净利润至少 30%；应收账款净额增速比营业收入增速高至少 20 个百分点；存货净额增速比营业成本增速高至少 20 个百分点。每条触发计 25 分。所有输入必须唯一、同公司同源、期间角色/单位/币种/报表口径相容，且逐条通过独立事实核验；提取与核验 evidence ID 不得重叠。调用约定使用同一进程直接由 `verify_financial_fact` 返回的结果；`VerificationResult` 是状态对象而非签名 proof，审计 JSON 或手工重建对象不构成核验凭据。规则 3、4 使用当前报告签发的年度可比性 proof，任一增长率的比较期基数小于等于 0 时该规则弃权。任一规则不可计算，则汇总总分为 `None`，不得将部分分数解释成总分。阈值为待验证试行值，不是经评测校准或确认舞弊的结论。海天真实 PDF 的四规则组合已通过独立可选 `--with-m3-screening` CLI 路径运行并正式归档 `annual-analysis-5e7079fe-9ac9-4e96-85fa-1898f9177d21`；默认 M2 CLI 与旧预检筛查不变。该路径使用旧四项 M2 事实的原 PDF 独立核验证据构造显式单位副本并再次核验；`non_recurring_total` 副本仅作审计，不作为规则输入或必需条件。 Markdown 报告中的计算值最多显示 6 位小数，JSON 审计副本保留未舍入 Decimal 原值，阈值判断在舍入前完成。

结论需绑定事实、计算和引用依据。v2 已定义 `fact`、`calculation`、`inference`、`hypothesis` 主张类型；同比属于 `calculation`。异常信号用于提示进一步核查，不等同于确认舞弊。未知追溯状态不能默认两年可比。上期为零或负数时可以保留差额，增速弃权。非经常性损益披露合计不直接除以归母净利润。v2 确定性 CLI 已在海天样例中独立核验八条事实和八项计算、检查 16 条确定性 Claim，并保留两条候选线索。当前报告内的可比性 proof 受进程签名保护；其序列化结果只用于审计，而且没有独立勾稽此前已披露的 2023 年报。以上只覆盖一份年报，不代表泛化。旧年度预检及历史 JSON 保持原样，旧预检字段结构的审计见 [current-schema-audit.md](current-schema-audit.md)。

- 记录文件访问以及实际模型请求、响应、调用时间、模型版本或供应方返回标识、用量和关键结构化结果；记录前移除密钥、鉴权头等敏感凭据。不能只记录提示词模板或随机种子来声称在线模型结果完全可复现。
- .env.example 不包含真实凭据；实际密钥通过环境变量或本地 .env 配置。
- 第一版使用云端 API：原始材料、索引、统计计算与运行记录留在本地；后端只发送公开或获准外发的必要片段，并记录对应文档和页码。第一版不将整库、评测标签或事后处罚材料上传给模型，也不开放任意互联网检索；模型端点和资料白名单独立管理。现场联网范围按比赛环境要求落实。
- 复现说明应交代重新计算与历史输出回放的区别，不能把读取已有报告描述为实时分析。

## 6. 样例与评测

- data/samples/ 用于演示输入；案例清单、人工期望和标签进入 evaluation/cases/。
- 对真实数据、脱敏数据和人工构造数据分别标明性质及处理方法。
- 历史案例分析只使用截止分析时点已公开的材料，记录材料可用时间。
- 后续处罚信息、事后调查结论及人工答案只用于评测，不能进入该案例的历史分析检索范围。
- 对照方案使用相同输入和评测口径；记录样本范围，避免用少量演示案例声称已验证泛化能力。
- 未发现处罚或公开舞弊记录的公司不能直接标记为“已确认无舞弊”，需明确对照样本的标注依据。
- 样本单位为“公司 + 报告期”；标签另附报告类型、受影响文件、处罚所认定的财务事项、受影响期间及标签截止日。只有明确涉及财务虚假记载等事项并能映射到相关财报的认定才作为相应正例依据；一般违规处罚不直接当作财报舞弊标签。
- 区分分析材料截止时间与评测标签观察截止时间。例如后续处罚认定早期财报存在问题，标签对应受影响的早期财报，处罚文本只进入隔离的评测标签区。
- 开发、验证和测试以公司隔离，并设置报告披露时间边界；同一公司的相邻报告期、同一财报的修订版本及衍生片段不得跨集合泄漏。训练集内才能拟合预处理、采样或平衡处理，验证集用于规则与阈值选择，测试集锁定后不参与调参。
- 测试集尽量保留目标使用场景的类别比例；若另建正例富集的压力案例集，应分开报告。未确认对照与未知样本的处理、弃权比例和数据覆盖率必须随指标披露。

首个 M4 消融协议 `evaluation/verification_ablation_cases_v1.json` 与脚本 `scripts/evaluate_verification_ablation.py` 使用海天 603288 2024 年报原始 PDF 的收入表格行作为 clean 参考，并定义错金额、错单位、错年度/期间、错报表口径和无支持 Claim 五类合成错误。clean 值由 agent 按 PDF 转录，尚未经人工审核，不能称为人工 golden；注入标签只对受控变异成立，不是处罚或舞弊标签。运行 `verification-ablation-m4-20260928T072029Z-825a8c4b` 的七个已知案例为两个 clean 对照和五个注入案例；茅台与五粮液的两个 provisional 案例为未知状态对照，排除在准确率、拒绝率和覆盖率分母之外。核验支路调用当前事实/Claim 核验器；绕过支路的接受规则及逐例哈希、出处和结果写入 `artifacts/evaluations/<evaluation_id>/`。详细统计与限制见运行目录的 `summary.json`，此结果不代表完整 M4 验收。

## 7. 临时文件与清理

临时文件统一放入 tmp/<task_id>/，就近归属于相关模块；公共临时位置为 artifacts/tmp/<task_id>/。正式样例、报告和复现证据不依赖这些目录。

临时内容转为长期资产前，应整理命名、来源、文档和相关检查，再迁入对应正式目录。已有 tmp/、任务子目录及其中临时文件默认保留，任务结束不主动清理。

仅在用户明确要求清理时，先核对归属和绝对路径范围，再清理获准且确认不再需要的内容；不删除未知任务内容、用户资料或必要证据。自动化清理机制尚未实现，执行清理时由协作者按 AGENTS.md 完成核对。
